Lige nu er rumskibet lidt for nemt at styre. Det stopper med det samme, når du slipper pil-op. Sådan er det ikke i rummet!

I rummet er der ingen luft. Der er altså intet, der bremser dig. Hvis noget først er i gang med at flyve, så **bliver det ved** med at flyve, indtil noget andet skubber til det. Det fandt en klog mand ved navn Isaac Newton ud af for mange år siden.

Efter dette niveau:

- giver pil-op et lille **skub** i den retning, næsen peger
- glider rumskibet videre, når du slipper tasten
- kan du dreje rundt og flyve "baglæns" eller sidelæns

## Det nye i dag: heading og track

Der er to forskellige retninger at holde styr på:

- **Heading** er der, hvor **næsen peger**. Det er den, du ændrer med pil-venstre og pil-højre. Du kender den allerede fra turtle: `player.heading()`.
- **Track** er der, hvor du **faktisk flyver hen**.

Indtil nu har de to altid været ens, for vi brugte `player.forward(...)`, som flytter turtlen lige frem i næsens retning. Men tænk på en skøjteløber: Hun kan glide fremad og samtidig dreje hovedet og kroppen til siden. Hun peger én vej, men glider en anden vej. Sådan bliver det med vores rumskib.

### Fart i to dele: speedx og speedy

For at rumskibet kan glide i én retning og pege i en anden, skal det huske sin fart. Vi deler farten op i to tal:

- `speedx` er hvor meget rumskibet flytter sig **til højre** hver gang i game loop (negativ betyder til venstre).
- `speedy` er hvor meget det flytter sig **opad** (negativ betyder nedad).

Hvis `speedx` er 3 og `speedy` er 0, flyver rumskibet lige til højre. Hvis begge er 2, flyver det skråt op mod højre.

### Et skub i næsens retning: cos og sin

Når du trykker pil-op, skal rumskibet få et lille skub i den retning, næsen peger. Men vi skal vide, hvor meget af skubbet der går **til siden** (x), og hvor meget der går **opad** (y). Det kan matematik-funktionerne `math.cos` og `math.sin` regne ud for os:

- `math.cos(vinkel)` siger, hvor meget af et skridt der går til siden.
- `math.sin(vinkel)` siger, hvor meget af et skridt der går opad.

Der er bare én ting: `math` regner ikke i grader, men i noget, der hedder **radianer**. En hel omgang er 360 grader, men cirka 6,28 radianer. Du behøver ikke kunne regne om selv, for `math.radians(grader)` gør det for dig.

Prøv det her. Programmet tegner en pil i en bestemt retning og viser, hvor meget af pilen der går til siden (orange) og opad (blå):

```python.run
import turtle
import math

heading = 30   # grader: 0 = højre, 90 = op, 180 = venstre
length = 150   # hvor lang pilen er

angle = math.radians(heading)
x = length * math.cos(angle)
y = length * math.sin(angle)
print("Til siden (x):", round(x, 1))
print("Opad (y):", round(y, 1))

t = turtle.Turtle()
t.color("orange")
t.goto(x, 0)
t.color("blue")
t.goto(x, y)
t.penup()
t.goto(0, 0)
t.pendown()
t.color("red")
t.goto(x, y)
```

### En maksimal fart

Hvis du holder pil-op nede længe, får rumskibet et skub igen og igen. Så ville det blive hurtigere og hurtigere for evigt. Det er ikke sjovt at spille, så vi laver en **max fart**.

Men hvor hurtigt flyver rumskibet egentlig, når farten er delt op i `speedx` og `speedy`? Her hjælper **Pythagoras**: Den rigtige fart er den skrå side i en retvinklet trekant, hvor de to andre sider er `speedx` og `speedy`.

- fart = √(speedx² + speedy²)
- I Python skriver vi `(speedx ** 2 + speedy ** 2) ** 0.5`. `** 2` betyder "i anden", og `** 0.5` betyder kvadratrod.
- Eksempel: speedx = 3 og speedy = 4 giver √(9 + 16) = √25 = 5.

Hvis farten er for stor, gør vi **både** `speedx` og `speedy` lige meget mindre. Så flyver rumskibet stadig i samme retning, bare ikke hurtigere end max.

Prøv at køre denne lille simulation. Rumskibet giver gas mod højre (heading 0) i 3 ticks, drejer så op (heading 90) og bliver ved med at give gas:

```python.run
import math

PLAYER_THRUST = 1
PLAYER_MAX_SPEED = 5
speedx = 0
speedy = 0
heading = 0

for tick in range(8):
    if tick == 3:
        heading = 90  # drej næsen op
    angle = math.radians(heading)
    speedx += PLAYER_THRUST * math.cos(angle)
    speedy += PLAYER_THRUST * math.sin(angle)
    speed = (speedx ** 2 + speedy ** 2) ** 0.5
    if speed > PLAYER_MAX_SPEED:
        speedx = (speedx * PLAYER_MAX_SPEED) / speed
        speedy = (speedy * PLAYER_MAX_SPEED) / speed
        speed = PLAYER_MAX_SPEED
    print(f"Tick {tick}: heading={heading} speedx={round(speedx, 2)} speedy={round(speedy, 2)} fart={round(speed, 2)}")
```

Læg mærke til, at `speedx` ikke forsvinder, når næsen peger op. Rumskibet glider stadig mod højre, mens det langsomt får mere fart opad. Og farten stopper ved 5.

:::tip[Prøv at ændre]
- Sæt `PLAYER_MAX_SPEED` op til `100`. Hvad sker der med farten?
- Prøv `heading = 180` i stedet for `90`. Hvad sker der med `speedx`? Det er sådan, man bremser i rummet: man vender sig om og giver gas den anden vej!
:::

### Player.thrust() – giv rumskibet mere fart!

Nu laver vi en ny metode, som giver rumskibet et lille skub i den retning, næsen peger. Den gør det samme som simulationen ovenfor:

```python
    def thrust(self):
        track = math.radians(self.heading())
        self.speedx += PLAYER_THRUST * math.cos(track)
        self.speedy += PLAYER_THRUST * math.sin(track)
        speed = (self.speedx ** 2 + self.speedy ** 2) ** 0.5
        if speed > PLAYER_MAX_SPEED:
            self.speedx = (self.speedx * PLAYER_MAX_SPEED) / speed
            self.speedy = (self.speedy * PLAYER_MAX_SPEED) / speed
```

Linje for linje:

1. `track = math.radians(self.heading())` finder næsens retning og regner den om til radianer. Det er den retning, skubbet kommer i. (Variablen hedder `track`, fordi det er den retning, vi skubber rumskibets kurs hen imod.)
2. `self.speedx += ...` lægger den del af skubbet, der går til siden, oven i farten i x.
3. `self.speedy += ...` lægger den del af skubbet, der går opad, oven i farten i y.
4. `speed = ...` regner den samlede fart ud med Pythagoras.
5. `if speed > PLAYER_MAX_SPEED:` er sand, når rumskibet er blevet for hurtigt. Så gør vi både `speedx` og `speedy` mindre, så farten bliver præcis `PLAYER_MAX_SPEED`, og retningen er den samme.

Læg mærke til, at vi bruger `+=`. Vi lægger skubbet **oven i** den fart, rumskibet allerede har. Vi starter ikke forfra.

- [ ] Sæt koden ind i `Player` klassen, efter **hele** `def hit(self):` blokken (altså efter linjen `self.alive = False`). `def thrust(self):` skal være rykket lige så meget ind som `def hit(self):`.

### Player.move() – flyt rumskibet!

Nu skal rumskibet flytte sig ud fra sin fart:

```python
    def move(self):
        x, y = self.pos()
        x += self.speedx
        y += self.speedy
        self.goto(x, y)
```

- `x, y = self.pos()` henter rumskibets position. `pos()` giver to tal tilbage på én gang, og her gemmer vi det første i `x` og det andet i `y`.
- Så lægger vi farten til positionen.
- Til sidst flytter vi rumskibet til den nye position med `goto`.

- [ ] Sæt koden ind i `Player` klassen, efter hele `def thrust(self):` blokken

    # Border checking for bullet
    x = t.xcor()

    if check_collision(player):
        player.hit()


def move_bullets():
    player.cooldown()
    inactive_bullet = None
    for bullet in bullets:
        if bullet.active:
            bullet.move()
            hit_asteroid = check_collision(bullet)
            if hit_asteroid:
                hit_asteroid.hit()
                bullet.hideturtle()
                bullet.active = False
                player.score += 1
                draw_score()
        else:
            inactive_bullet = bullet

    if keys_pressed["space"] and inactive_bullet:
        player.shoot(inactive_bullet)


def move_asteroids():
    for asteroid in asteroids:
        if asteroid.isvisible():
            asteroid.forward(asteroid.speed)
            move_if_out_of_bounds(asteroid) # let the kids figure this one out for a while
            # also this one:
            if abs(player.distance(asteroid)) < asteroid.radius:
                player.hit()
        else:
            asteroid.respawn_in -= 1
            if asteroid.respawn_in == 0:
                asteroid.reset()


def draw_score():
    score_pen.clear()
    score_pen.write(player.score, font=SCORE_FONT)


def draw_health():
    health_pen.clear()
    health_pen.write(player.health, font=SCORE_FONT)


#
#  GAME LOOP
#

def update():
    move_spaceship()
    animate_spaceship()
    move_bullets()
    move_asteroids()

    screen.update()
    if player.alive:
        screen.ontimer(update, GAME_TICK) # this calls the game loop again for the next tick
    else:
        pen.goto(0, 0)
        pen.write("GAME OVER", align="center", font=(FONT_FAMILY, 68, "normal"))


#
#  START THE GAME
#

draw_score()
draw_health()
update() # call the game loop to start the game
screen.mainloop() # don't close the window
